KV Cache

推理时模型权重一动不动，真正吃显存的是这份随每个 token 膨胀的「对话记忆」。本页算清它的账：为什么缓存的是 K 和 V、一个 token 值多少字节、以及公式里每个因子都是压缩旋钮。

图解 + 公式 交互计算器 ≈ 12 分钟 下篇：PagedAttention
LAYER 1

直觉：生成是滚雪球，显存是斜坡

本层目标：一张图 + 三个数字，建立「KV Cache 随生成线性膨胀」的直觉。

图 1 · 自回归生成：每一步都背着全部历史

上：token 序列逐个生成。下：KV 占用是一条从 0 出发的直线 —— 斜率恒定 = 每 token 单价固定，序列多长直线多长，直到序列结束才整条释放。

512KB

LLaMA-7B 每个 token 的 KV 身价（fp16）—— 一个汉字的缓存 ≈ 一张小图

1.0GB

同一个模型一条 2048 token 序列的 KV —— 权重才 14 GB，一条长对话就吃掉 1/14

32GB

Qwen3-32B 单条 128k 长上下文序列的 KV —— 一张 A100 装一条序列就快满了

一句话：权重是「房租」（固定），KV Cache 是「水电费」（按用量线性计费，按并发叠加）—— 服务容量被水电费锁死。

认知检查 · LAYER 1

对话结束后该请求的 KV Cache 会怎样？

KV Cache 是请求级临时数据，随请求生灭。这就是多轮对话「重新发全文」的原因 —— 也是 PagedAttention 的 prefix caching（块级复用）能白省 30%+ 的空间所在。
LAYER 2

原理：为什么缓存的是 K 和 V，不是 Q

本层目标：一张图 + 一行公式，看懂「K/V 必须全量保留、Q 用完即弃」。

图 2 · 注意力的不对称：Q 只需要当前行，K/V 需要全部行

生成第 t 个词：新 token 投影出 q_new（1 行），去和历史 每个 K 行算相似度，再对 每个 V 行加权求和。历史的 K、V 行行都被用到 —— 丢一行就失忆一段。

score(q_new, k_i) = q_new · k_i   →   输出 = Σ softmax(score)_i · v_i 每个历史位置的 k_i、v_i 都参与计算 ⇒ 必须缓存；q_new 算完即弃 ⇒ 无需缓存
不缓存：第 t 步重算 t 行 K/V ⇒ 总计算 L(L+1)/2 ∈ O(L²)；缓存后每步只算增量 ⇒ O(L) 本质是一笔交易：用 O(L) 的显存，买掉 O(L) 级的重复计算（L²→L）
认知检查 · LAYER 2

为什么历史 token 的 Q 不需要缓存？

注意力是「新 token 对历史的查询」：查询方永远只有当前行，被查方（K）和取值方（V）是全部历史。不对称的角色 ⇒ 不对称的缓存策略。
LAYER 3

尺寸：一个 token 值多少字节

本层目标：一个公式拆出每个因子，再横向对比真实模型。

图 3 · per-token 尺寸分解（以 LLaMA-7B 为例）

每层的每个 KV 头存一组 128 维向量 ×2（K 和 V）×2 bytes，再乘全部 32 层 —— 512 KB / token。注意：这个数与序列长度无关，是「单价」。

KV(单序列) = 2 · nlayers · nkv_heads · dhead · L · b L = 序列长度（token 数），b = 精度 bytes（fp16=2, int8=1）。单价 × 数量 = 总账
图 4 · 真实模型横向对比：MHA vs GQA 是分水岭

同为 ~8B 级：LLaMA-7B(MHA) 512 KB/token vs LLaMA-3-8B(GQA-8) 128 KB/token —— 4 倍差距全在 kv_heads 一个因子上（32→8）。模型更大不等于 KV 更贵。

认知检查 · LAYER 3

A100-80GB 跑 LLaMA-2-13B（26 GB 权重，预留 2 GB 激活），4k 上下文单序列 KV = 3.13 GB。最多同时服务几路？（容量按 100% 利用算）

52 / 3.13 ≈ 16.6 ⇒ 16 路。这是理论上限 —— 实际系统因预留与碎片只能装一半左右，正是 PagedAttention 要解决的问题。
LAYER 4

压缩：公式里的每个因子都是旋钮

本层目标：四个压缩方向 + GQA 机制图，理解「压的是缓存不是模型」。

图 5 · 四个旋钮（按公式因子分类）

公式 KV = 2 · layers · kv_heads · d_head · L · b 中，除常数 2 外每个因子都被工程动过 —— 旋钮效果相乘。

图 6 · GQA：Query 头分组共享 K/V（红绿分水岭的由来）

Q 头数量不变（不伤表达能力），只把「缓存端」的 K/V 头数砍掉 —— 32 头共享 8 份 KV。压的是缓存，不是模型本体。MQA 是极限版（全部共享 1 份，32x），代价是质量下降。

认知检查 · LAYER 4

GQA 把 KV 从 32 份压到 8 份，为什么模型质量几乎不掉？

GQA 训练时 query 头仍各算各的注意力（对着共享 K/V 的不同投影视角），表达能力保留在 Q 侧。这是「压缓存不压模型」最漂亮的一招，现代模型（LLaMA-3 / Qwen3 / Mistral）全用它。

5.1部署现象对照表

现象根因对应本页概念
并发一高就 OOM，单跑没事KV 随并发叠加，池被榨干单价 × 并发（L1/L3）
长对话越聊越慢注意力对全部 KV 扫描，计算也随 L 增长O(L) 递增（L2）

带走的五句话

  • 权重是固定房租，KV Cache 是按 token 计费的水电费 —— 推理容量被它锁死（L1）
  • 缓存 K/V 不缓存 Q：查询方只有当前行，被查方是全部历史 —— 用 O(L) 显存买掉 O(L²) 重算（L2）
  • 单价 = 2·layers·kv_heads·d_head·bytes；总量 = 单价 × L × 并发（L3）
  • MHA vs GQA 是 4 倍分水岭：压缓存不压模型，Q 侧表达力全保留（L4）
  • 所有压缩旋钮按因子相乘；碎片与复用问题交给下篇 PagedAttention（L5）

术语速查

自回归 (autoregressive)
逐 token 生成，每步以全部历史为条件 —— KV 直线的来源。
MHA / MQA / GQA
多头注意力的 KV 头配置：每 Q 头独立 / 全共享 1 份 / 分组共享。KV 份 = kv_heads。
per-token 单价
2·n_layers·n_kv·d_head·b 字节。与序列长度无关，与并发无关。
prefix caching
跨请求复用相同前缀的 KV；多轮对话 / 共享 system prompt 场景大幅省显存。
KV 量化
把缓存的 fp16 K/V 压成 int8/int4 —— 只压缓存，不动权重。
