PagedAttention

大模型推理时，90% 的显存装的是 KV Cache —— 它怎么存、怎么分、怎么复用，决定了你的 GPU 能同时服务多少人。vLLM 用一个操作系统级的想法解决了它。

LAYER 1

问题：显存瓶颈不在模型，在 KV Cache

本层目标：一张图 + 三个数字，看清要解决什么。

图 1 · 一个推理请求的一生（横轴 = token）

prompt 一次性预填充写入 KV；之后每生成 1 个 token 追加 1 份 K 和 V —— 显存占用是斜率恒定的直线，直到序列结束才释放。

KV 显存(单序列) = 2 (K,V) × nlayers × nkv-heads × dhead × ℓ × b ℓ = 序列长度，b = 2 bytes (fp16)。每生成一个 token，此式 +1 份增量
0

13B 模型权重 ~26 GB，并发 50 请求的 KV Cache 需求可达其 10 倍量级 —— 服务能力被 KV 显存锁死

0

旧系统（FasterTransformer / Orca）KV Cache 显存利用率实测仅 20.4%–38.4%，其余全是预留与碎片浪费

0

vLLM：同 GPU 同模型，吞吐最高 24 倍提升 —— 靠的不是更大的模型，是更聪明的存法

问题本质：权重只读且尺寸固定；KV Cache 随请求动态到达/结束、长度不可预知 —— 它是唯一需要「动态内存分配」的大块显存。这题操作系统 60 年前就解过。

认知检查 · LAYER 1

推理服务的第一瓶颈为什么是 KV Cache 的「管理方式」而不是模型本身？

权重静态可精确规划；KV Cache 动态增长、长度不可预知，分配策略决定同样 80 GB 显存能装几个请求 —— 利用率从 30% 提到 96%+，等于免费扩容 3 倍。
LAYER 2

KV Cache：为什么缓存、为什么线性膨胀

本层目标：两张图 + 一个公式，看懂 KV Cache 的必要性与增长规律。

图 2 · 没有缓存：每步重算全部历史 K/V —— O(L²) 重复劳动

生成第 t 个词需要全部前文的 K、V —— 若不缓存，第 t 步重算 t 行。总计算 ∑t = L(L+1)/2 ∈ O(L²)，其中绝大部分是重复。

图 3 · 有缓存：每步只算增量 1 行 —— O(L) 显存换 O(L) 计算

左：K/V 矩阵逐行追加，橙色 = 本步新增行。右：显存占用对 L 严格线性 —— 这条直线的斜率就是上一层的公式。

KV(L) = 2 · nlayers · nkv · dhead · L · b   →   LLaMA-7B, L=2048, fp16: 2×32×32×128×2048×2 = 1.0 GB / 序列 A100-80GB 除去 14 GB 权重，理论上限 ≈ 66 个并发 —— 若利用率 100%。旧系统实际只装 ~20 个
认知检查 · LAYER 2

LLaMA-7B（n_layers=32, GQA 关闭 n_kv=32, d_head=128, fp16），单序列 L=2048 的 KV Cache 是多大？

2×32×32×128×2048×2 = 2³⁰ bytes = 1.0 GB。直觉：KV 随长度线性、随并发叠加 —— 两把刻度尺一起量出服务容量。

3.2连续分配的死刑判决书 —— 外部碎片

外部碎片 = 总空闲 − 最大连续空闲段   ⇒   S7 时刻 = 24 − 12 = 12 格（占池 12%） 碎片不是「坏掉的显存」，是「被位置困住的显存」—— 加内存救不了，新内存同样会碎

操作系统给出了全部候选答案：压缩整理（要搬迁正在服务的序列，停机不可接受）、best-fit / buddy（缓解不根治）、分页（直接放弃连续性约束）—— vLLM 选了最后这个。

认知检查 · LAYER 3

策略二在 S7 卡死：总空闲 24 ≥ 需求 22。为什么 E 进不来？

教科书级外部碎片。best-fit 无解（甚至更碎），压缩需停机搬迁在线序列。唯一根治：砍掉「必须连续」这个约束 —— 把序列拆成固定小块，散布存放，块表索引。这就是 LAYER 4。
LAYER 4

PagedAttention：把操作系统装进 Attention

本层目标：两张结构图 + 一张流程图，看懂 vLLM 论文 Fig. 2/3 在说什么。

4.1虚拟地址 → 块表 → 物理块

图 4 · 逻辑连续，物理离散（对应论文 Fig. 3）

每个序列持一张块表：逻辑块号 → 物理块号。注意力核直接按块表寻址 gather K/V —— 逻辑上序列是连续的，物理上块散布全池。

浪费上界 = 每序列 < 1 块  ⇒  平均 B/2 槽位  ⇒  vLLM 实测浪费 < 4%（论文 Fig. 6） 对比：预留制 ~60%、连续制碎片 30%+ —— 一个数量级的差距

4.2decode 一步的完整流程

图 5 · 生成一个 token 的全流程（含新 K/V 落块逻辑）

读块表 → 逐物理块 gather K/V → attention → 采样出新 token → 算它的新 K/V → 末块有空位则写入，否则申请新物理块。虚线 = 回到下一步。

4.3白送的能力：物理块级复用

图 6 · prefix 共享：system prompt 只存一份（写时复制）

连续分配下不可能：块物理复用要求「同一份数据多处引用」，只有块表间接层才做得到。多轮对话 / 共享 system prompt / beam search 候选共享，显存再省 30%+。

认知检查 · LAYER 4

序列 A 的逻辑块 7 → 物理块 3，逻辑块 8 → 物理块 17。注意力核因此必须做什么？

这正是虚拟内存精髓：连续的是逻辑视图，散布的是物理存储。代价是注意力核从「读连续矩阵」变成「查表 + 逐块 gather」—— vLLM 为此专门重写了 CUDA kernel，在 kernel 内解析块表。

带走的五句话

  • 推理显存大头是 KV Cache：2·n_layers·n_kv·d_head·L·b，随长度线性、随并发叠加（L1-L2）
  • 缓存是必须的：不缓存则计算 O(L²)，缓存后 O(L) —— 用显存买计算（L2）
  • 预留制死于预留浪费，连续制死于外部碎片 —— 空闲总量够、位置不连续，加内存无用（L3）
  • 分页：逻辑连续物理离散，块表寻址，浪费 < 4%；块级复用让 prefix 共享成为白送能力（L4）
  • 同硬件吞吐 7.5–14x：没有新模型、没有新数学，只是把操作系统装进了 attention kernel（L5）

术语速查

KV Cache
注意力 K/V 的增量缓存：避免 O(L²) 重算，代价 O(L) 显存。
内部碎片
块内已分配未使用的槽位。分页下每序列最多浪费 < 1 块。
外部碎片
空闲总量足够但位置不连续。预留制无此问题但有预留浪费；连续制被它锁死。
块表 (block table)
逻辑块 → 物理块的每序列映射表，注意力核的寻址依据。
写时复制 (copy-on-write)
多个序列共享物理块，仅在内容分歧点才复制 —— beam search / prefix 共用的基础。
prefix caching
跨请求复用相同前缀的物理块；多轮对话场景大幅省显存。

延伸路线：FlashAttention（计算角度）· Continuous Batching（调度角度）· Speculative Decoding（生成角度）—— 推理加速的另外三条战线。
