RAG / Embedding

模型的知识冻结在训练截止日：问昨天的财报它编一个，问公司 wiki 它幻觉。RAG 的思路朴素 —— 检索相关文档拼进上下文再生成 —— 背后的魔法是 embedding：把文字变成向量后，「语义相近」变成「余弦相似度高」。拖动粉色查询点，亲眼看「猫狗老虎」抱团、「汽车卡车」扎堆。

向量空间拖拽 余弦相似度 约 10 分钟 前置：Tokenizer
LAYER 1

死穴：背下来的知识会过期

本层目标：理解参数化知识的三个边界 —— 过期、私有、幻觉。

图 1 · 三个必错的问题

预训练把知识「烧」进权重（回忆 RLHF 页：预训练学世界怎么运转）。参数是静态快照：训练截止日之后的世界、从未见过的私有数据，它一无所知 —— 但下一词预测的本能（Tokenizer 页）让它照常输出，于是有了幻觉。RAG 换思路：不更新参数，把「查到的资料」放进上下文。

认知检查 · LAYER 1

RAG 为什么比微调更适合「知识更新频繁」的场景？

「外挂书架」vs「重写大脑」。知识频繁变 → 外挂；风格/领域语感稳定 → 才轮到微调。两者不互斥（L5）。
LAYER 2

向量空间：语义的几何学

本层目标：拖动查询点，建立「余弦相似度 = 语义距离」的手感。

图 2 · 语义散点（拖动粉色查询点！）

Embedding 模型把每段文字映射成高维向量（真实是 768-4096 维，这里 2D 示意）。语义近 → 夹角小 → cos 接近 1。拖动查询点：靠近「猫狗」时 cos≈0.997，滑向「汽车」时猫狗掉到负值 —— 模型没有「动物」的概念表，但几何自动聚了类。注意：检索看的是夹角不是距离（长度常代表词频类的信号，要除掉）。

图 3 · 向量算术：国王 − 男人 + 女人 ≈ 女王

方向携带语义：把「国王」向量里的「男性」分量减掉，加上「女性」分量，结果落在女王附近（cos=0.917）。这种线性结构是 embedding 最著名的性质 —— 说明维度不是乱码，而是学到了可解释的概念方向（word2vec 时代发现，现代 embedding 依然保持）。

cos(a, b) = (a·b) / (‖a‖·‖b‖) · 值域 [−1, 1] · 越大越相似 只看方向不看长度。真实向量 768-4096 维 —— 2D 是给它开的「可视化窗口」
认知检查 · LAYER 2

为什么用余弦相似度而不是欧氏距离？

一个短句和一个长文档谈同一件事，向量可能同方向不同长度 —— 余弦说「同类」，欧氏距离说「很远」。检索要的是前者。
LAYER 3

流水线：离线建索引，在线百毫秒

本层目标：记住两条流水线 —— 离线一次、在线每查。

图 4 · 完整 RAG 流水线

离线：文档 → 切 chunk → embedding → 向量库（ANN 索引，百万级向量毫秒检索）。在线：查询 → 同一 embedding 模型向量化 → ANN 取 top-k → （可选）rerank 重排 → 拼进 prompt → 生成。查询与文档必须同一个 embedding 模型 —— 两套坐标系无法比较。

认知检查 · LAYER 3

ANN（近似最近邻）为什么牺牲一点召回换速度？

「先粗筛后精排」是检索系统通用架构：ANN 粗召回 50 → cross-encoder 重排取 5 —— 重排模型看得慢但看得细（逐对打分）。
LAYER 4

chunk：检索的粒度艺术

本层目标：理解 chunk 大小与重叠的权衡。

图 5 · chunk 切分与重叠

chunk 太小 → 语义被切碎，检索到的片段缺上下文；太大 → 向量被稀释（一段谈三件事，哪个都不像）。经验起点：512 token + 12.5% 重叠（Tokenizer 页的 token 口径）。重叠的作用：关键句跨边界时至少有一个 chunk 含完整语义。10k token 文档 → 23 chunks，检索 top-5 只带 2.5k token 进 prompt —— 证据要少而准。

图 6 · 检索的账单（13B fp16）

检索 30 页 = 15k token = 11.4GB KV（KV Cache 页口径 0.78MB/token）。多检索不是免费的 —— prompt 越长 prefill 越贵（FlashAttention 缓解）、注意力越分散。top-k 的 k 是精度与成本的旋钮，和 Reasoning 页的思考预算同构。

LAYER 5

落地：三方案对比与混合

本层目标：知道什么时候用 RAG、什么时候微调、什么时候直接塞。

方案建库/训练更新成本最适合
RAG索引几小时换文档即更（小时级）事实型知识、私有库、时效内容
微调数千 GPU 时重跑训练风格、领域语感、输出格式
长上下文无需零单文档深读（≤200k token 的合同/论文）
图 7 · 现实中的混搭
🏢 企业知识库问答：RAG 管事实（wiki 天天更新）+ 微调管语气（客服腔调）
📚 论文问答：长上下文单篇深读 + RAG 跨库检索 + 思考模型做多跳推理
🤖 Agentic RAG：思考模型自己决定「再查一次 / 换个关键词 / 够了可以答了」—— 检索从一次性动作变成多轮策略

带走的五句话

  • 参数化知识会过期、无私有、爱幻觉 —— RAG 用「查到的」补「背下来的」（L1）
  • embedding 把语义变几何：余弦相似度高 = 方向近；「猫−狗 + 汽车」的算术有效（L2）
  • 流水线两段式：离线建索引一次，在线检索百毫秒 —— 查询与文档同一 embedding 模型（L3）
  • chunk 512 tok + 12.5% 重叠是起点；top-k 是精度与成本的旋钮（L4）
  • RAG 管事实、微调管风格、长上下文管深读 —— 现实总是混搭（L5）

术语速查

Embedding
把文本映射成稠密向量（768-4096 维），语义近 → 向量方向近。
余弦相似度
两向量夹角的余弦，[−1,1] —— 检索的标准语义距离。
ANN (近似最近邻)
HNSW/IVF 类索引结构，牺牲少量召回把百万级向量检索压到毫秒级。
chunk
检索的基本单元 —— 文档切成的小段（典型 256-1024 token）。
rerank (重排)
cross-encoder 对「查询-文档」逐对精细打分，粗筛后的第二道关。
混合检索
BM25（关键词精确匹配）+ 向量（语义泛化）双路召回 —— 两类信号互补。
agentic RAG
模型自主决定查什么、查几次 —— 检索变成多轮策略（与思考模型天然配对）。
